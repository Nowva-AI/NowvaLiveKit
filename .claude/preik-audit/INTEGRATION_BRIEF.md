## 1. `utils/preik_chain.py` — the single chain definition (C10)
```python
class PreIKResult(NamedTuple):
    analysis: Skeleton3D            # hip-centred, fixed-lag (2 frames) — IK/rules/buffers use this
    display: Skeleton3D | None      # hip-centred, undelayed — HUD/avatar
    analysis_world: Skeleton3D | None  # world frame lagged (multi-camera only) — for body calibration + foot metrics
    foot_state: FootState | None    # multi-camera only
    velocities: np.ndarray          # (N,3) m/s at analysis time
class PreIKChain:
    stage_names: tuple[str, ...]
    def run(self, skeleton: Skeleton3D) -> PreIKResult | None      # None = hips unavailable (dropout path)
    def predict_missing(self, timestamp: float) -> PreIKResult | None
    def reset(self) -> None        # temporal state only (Kalman); foot contact is session-scoped and NOT reset
    def set_tap(self, tap: Callable[[str, np.ndarray, np.ndarray], None] | None) -> None  # inspector hook: (stage, points, confs)
def build_preik_chain(config: BiomechanicsConfig, multi_camera: bool) -> PreIKChain
```
Multi-camera: input is WORLD frame → `FixedLagKeypointSmoother` (C3-derived R) → `FootContactModel.update(lagged_world, lagged_conf, lagged_ts)` → `recentre_at_hips` for `analysis` and (from current stream) `display`. Single-camera (MediaPipe, already hip-centred): `FixedLagKeypointSmoother` with `measurement_std_floor_m` from `config.kalman.single_camera_measurement_std_floor_m` (start 0.01) → no foot contact. Convert Skeleton3D↔numpy exactly once at entry and exit; tap after each stage. Keypoint-count agnostic (17/19/21).
