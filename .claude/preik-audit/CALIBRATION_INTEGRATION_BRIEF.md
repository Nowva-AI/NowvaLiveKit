## Behaviour to build
1. **Provider capture buffer.** `MultiCameraPoseProvider` keeps a ring buffer (config `calibration_buffer_frames`, default 450) of per-frame `views` dicts (raw-pixel Skeleton2D per camera, only frames with ≥ 2 cameras) and, when a `BarbellDetector` is available (config `barbell_tracking.enabled` or a new `camera_calibration.use_bar_scale`, model present), bar-end detections per camera for the same frames, run on every camera frame at a reduced rate (every `bar_detection_stride` frames, default 3) only while a capture window is open (`begin_calibration_capture()` / `end_calibration_capture()`), never during normal sets. Expose `calibration_views()`, `calibration_bar_ends()`, `recent_views(n)`.
2. **2D-only operation before a calibration exists.** `get_pose()` must run capture + RTMPose and fill the buffer even when there is no triangulator yet (returns `(frame, primary_2d, None)`), so the person-based calibration can bootstrap with no T-pose.
3. **Intrinsics.** Use the ACTUAL opened resolution per camera (expose it from `MultiCameraCapture`) for `load_rig_intrinsics`; config `camera_keys` (device id → key) passed through; when a camera has no intrinsics file log ONE clear warning naming the command to run (`scripts/tools/calibrate_cameras.py intrinsics --camera N`) and fall back to the guessed K.
4. **Session flow in `pipeline_process.py`** (multi-camera): load order = refined person calibration (`rig_calibration_path` with suffix `_refined`, if newer than the factory file) → factory/previous file → none. If none: open a capture window, HUD "CALIBRATING CAMERAS — step in and do two slow squats", collect until ≥ `min_calibration_frames` (default 240) frames with ≥ 2 views AND ≥ 2 squat-like excursions (2D knee-flexion proxy) or a timeout (then fall back to the existing T-pose `provider.calibrate` with a clear message), run `PersonCalibrator.calibrate(views, bar_ends, initial=None)` in a worker THREAD (never fork; on macOS Accelerate deadlocks in forked children), save with `TPoseCalibrator.save_calibration`, install it (`provider.install_calibration(result.calibration)` → rebuild `DLTTriangulator`, `reset_temporal_state()`), then continue to the normal assessment. If a loaded calibration has `world_anchor == "board"`, run one `refine(keep_world_frame=False)` on the assessment reps' views, install it, save as `_refined` (never overwrite the factory file).
5. **Drift monitor.** Store `rms_reprojection_px` with the calibration (in the JSON; add the field to save/load if WS-A didn't — if that means touching `calibration.py`, keep it to that one field). At each set boundary / rest start, compute `reprojection_health_px(calibration, provider.recent_views(150))`; if > `drift_ratio` (default 1.5) × stored, run `refine(calibration, views, bar_ends, keep_world_frame=True)` in a thread during rest, install on completion (before the next set's readiness gate), log before/after. Never mid-set.
6. **World-state reset on install.** `pipeline.on_calibration_changed(world_frame_changed: bool)`: always `self._preik.reset()` and provider `reset_temporal_state()`; when the world frame changed (initial calibrate, board→person re-anchor) also reset the foot contact model via a new `PreIKChain.reset_world_state()`. Body calibration (segment lengths) is NOT reset.
7. De-duplicate `pipeline_process._rig_calibration_path` → `calibration.rig_calibration_path`.
