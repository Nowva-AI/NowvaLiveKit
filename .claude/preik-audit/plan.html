Pre-IK Filter Rebuild

The pre-IK filters are not the main problem, and turning them back on would make the 3-camera pipeline worse. On a ground-truth simulator, every original stage except the velocity clamp hurt squat accuracy. The largest errors sit on either side of the filters: in how the 3D skeleton is built, and in the angle smoothing and prediction after IK. Several bugs in the 3-camera path are breaking live sessions today.

9 parallel audits 1 ground-truth squat simulator (real repo classes) 12 live or latent bugs 0 code changes so far
Finding

The filters remove faults instead of noise

The original full chain was worst on every metric. It added 112 ms of lag and cut 6° from knee flexion at the bottom. It also erased 53–100% of stance changes and pelvic list. Your decision to disable it was right.

Finding

The biggest errors are upstream and downstream

Low-confidence joints give a knee angle of exactly 0° on 25–28% of frames. With no person crop, joints are about 60 mm off in 3D. The angle filter after IK turns +0.9° of depth error into −9.5°.

Finding

One smoother does better than all of them

A single Kalman filter that waits two frames before committing (66 ms): knee error while moving 14.5° → 1.3°, depth bias −4.5° → +0.5°, 32 µs per frame, edge-friendly.

Fix first

Bugs breaking 3-camera sessions today

Ordered by impact on the demo loop (squat, diagnose, cue, improve). "Verified in code" means I read the lines myself; the rest were reproduced by the audit agents with scripts.

  • Critical

    Every rep ends the set

    The rep end time comes from the camera's perf_counter clock; the set timeout compares it against time.time(). The gap is always ~1.8 billion seconds, so the set closes and the readiness gate resets after each rep.

    session_tracker.py:111 · pipeline_process.py:1287 · multi_capture.py:94Verified in code; 3 reps → 3 set_complete events
  • Critical

    Fault cues fire once per session

    Triangulated skeletons always carry frame_index=0. Rule cooldowns count frames, so after the first fault the cooldown never expires. 6 reps with knee cave and forward lean: 1 cue each vs 6 and 3 with real indices.

    multi_camera.py:201 · knee_valgus.py:88 · rule_engine.py:153Verified in code; reproduced on the real pipeline
  • Critical

    Knee angle reads 0° mid-squat

    The triangulator scales confidence down to below 0.1 for poor reprojection; IK treats anything below 0.1 as missing and returns 0.0°. Flooring confidence alone cuts moving knee error 14.3° → 4.3° and final depth error −9.5° → −3.1°.

    triangulator.py:126 · analytical_ik.py:160, 262Verified in code; simulator: 25–28% of frames
  • Critical

    Returning users lose diagnosis

    Calibration mode measures the athlete, then the per-set reset wipes it. The database upsert saves None over the stored params, so the next session starts with diagnosis off.

    pipeline_process.py:827, 909 · calibration_utils.py:87Reproduced independently by two agents
  • Critical

    3D joints about 60 mm off

    RTMPose receives the full 1280×720 frame squashed to 192×256 with no person crop. The same error appears in every view, so reprojection can't catch it. Knee flexion error 6.0° vs 1.2° with a tracked crop.

    rtmpose.py:181Measured on real video (mirror test 7.9 px vs 1.15 px)
  • Critical

    Empty frames pass as people

    Keypoint scores go through a sigmoid, so every keypoint scores ≥ 0.53 even on a black image. All 26 keypoints clear the 0.3 threshold and hallucinated skeletons get triangulated.

    rtmpose.py:238Measured on blank, noise and background images
  • High

    Knee cave can read as bowed-out

    The valgus size comes from the pelvic axis but its sign from the hip-ankle line. With 15° toe-out a 10° knee cave reads −4.7° (varus).

    valgus.py:294–304Synthetic; logic read in code — confirm with a failing test
  • High

    Reps merge together

    The counter enters "bottom" only below 5 cm/s. A squat with no pause skips that band. Counts 5.4/6 today and 4.0/6 with better smoothing, so this must land before any smoothing change.

    hip_position_counter.py:245Reproduced on clean synthetic reps
  • High

    A quarter to half of frames never processed

    Sync always takes the newest main-camera frame before the side cameras deliver, and one miss drops the whole set. 26–45% of frames lost; a sequence-number prototype got 24–27 Hz with ~1% misses.

    multi_capture.py:111–145Simulated with the real class; not measured on hardware
  • High

    One bad camera drags a joint 15–29 cm

    Unweighted DLT with no view rejection. A single-view knee outlier gives 17–33° knee error; a left/right swap in one view moves all legs 24 cm. Best-subset plus swap test: 2–3° and 7 mm.

    triangulator.py:107–131Synthetic, real DLT code path
  • High

    Threshold scaling compounds and points the wrong way

    Body-proportion scaling multiplies thresholds again every set. Forward-lean thresholds count down from 180°, so "more lenient" becomes stricter. By set 4 the rule fires on any posture or never.

    forward_lean.py:50 · knee_valgus.py:64 · pipeline.py:388Live in calibration mode; worsens if bone calibration is re-enabled
  • High

    +Z is the athlete's back in 3-camera mode

    T-pose PnP places the cameras at −Z, so direction-dependent outputs (pelvis tilt sign, wrist x, hip rotation, possibly forward-lean sign) are mirrored against the docstrings.

    calibration.py:9–14 · analytical_ik.py:417Two agents independently; forward-lean impact unconfirmed

Sequence

Rebuild in four phases

Order matters. Filters can't be tuned against a broken front end, and removing the blender before the predictor would let shallow reps pass the depth check. Each phase ends with a paired simulator run against today's pipeline. Bug fixes start with a failing test.

A

Stop the live bugs

Small, independent diffs. None of them changes the filter design.

  • One wall-aligned clock stamped at capture
  • Real frame index from a capture sequence counter
  • IK returns NaN for missing joints; rules skip NaN; triangulator stops emitting conf×0.1 points
  • Athlete params kept for the whole session; DB upsert refuses to write None over stored params
  • Proportion scaling applied once from stored base thresholds; delete valgus_scale
  • Raw RTMPose score; map halpe26 heels to indices 19/20
  • Valgus sign fix (after a failing test confirms it)
Exit check
  • 3 reps → 0 set_complete events
  • Valgus cue fires on every faulty rep of 6
  • 0 frames with knee flexion exactly 0°
  • Thresholds identical after 4 sets
Simulator: moving knee error 14.3° → ~4.3°
B

Rebuild the front end

Make the 3D input trustworthy before any smoothing is tuned.

  • Tracked person crop, bootstrapped by one full-frame pass
  • Sequenced sync policy (≥2 cameras within 20 ms; skip processed references)
  • Best-subset triangulation, previous-frame tie-break, swap test
  • Metric per-joint uncertainty; world-coordinate output, centre at IK boundary
  • Parabola sub-pixel decode
Exit check
  • Real video mirror disagreement ≤ 1.5 px
  • Simulator p95 joint error ≤ 25 mm under outliers
  • ≥ 25 Hz processed with 3 cameras
Expected: joints ~60 mm → ~7 mm
C

Replace the temporal filters

One smoother, one stream, one chain definition.

  • Fix rep-counter bottom detection first (sign-aware, uses Kalman velocity)
  • Fixed-lag Kalman with gate replaces blend, clamp and One Euro
  • Remove angle filter and predictor from the analysis path; display uses the undelayed estimate
  • Bottom frame, trajectory and rep signal from the same smoothed stream
  • Per-rep symmetry evaluation
  • build_preik_chain(config) with an inspector tap; per-set resets clear temporal state only
Exit check
  • Depth bias within ±1°
  • Short knee cave loses < 25%
  • 6/6 reps counted, no-pause tempo
  • ≤ 2 false symmetry events per set
Simulator: knee RMS moving 14.5° → 1.3°
D

Body measurements and feet

Replace the two clamps with estimators that report the body instead of forcing it.

  • Session segment-length estimator (rigid segments, whole assessment, robust median)
  • Per-foot contact model producing FootState: heel rise, stance width, toe-out, hip height above floor
  • New three-tier heel-rise fault rule
  • Floor normal as gravity reference for lean and depth
Exit check
  • Pelvic list and stance change kept ≥ 0.9×
  • Heel rise kept ≥ 85%
  • Femur/tibia length within 5 mm
Simulator: ankle 2.8 → 0.5 cm

Decisions before code changes

Start Phase A now?

These are bugs that break sessions today, independent of the filter redesign.

Recommend: yes, immediately.

Extend scope past "pre-IK"?

Phase C removes the post-IK angle filter and predictor and fixes the rep counter and symmetry rule. That's where the measured depth error lives.

Recommend: approve.

Accept 66 ms analysis delay?

Cues play between reps and rule cooldowns are 1–5 s. The live avatar would draw the undelayed estimate.

Recommend: accept.

Single-camera MediaPipe path

Most fixes apply to both paths, but world-frame foot contact and triangulation only exist with 3 cameras. Supporting both doubles the tuning.

Recommend: keep it working, stop tuning for it.

Record real 3-camera sessions

No 3-camera recordings exist, so thresholds (gate radius, reprojection cutoff, Kalman noise) are set from simulation. Needed: 5+ sessions with deliberate valgus, heel rise, hip shift and forward lean, logging raw per-view 2D and calibration.

Needs you: before Phase C thresholds are final.

Height for T-pose calibration

3-camera calibration uses a hardcoded 1.885 m and is never reloaded. A 1.65 m user gets every length inflated 14%.

Recommend: read the user's profile height; persist calibration per rig (Phase B).

Confidence in these numbers

Caveats and evidence

  • Most accuracy numbers are synthetic. Real RTMPose noise, confidence and outlier rates were measured on 4 real videos. The per-view bias, occlusion and swap rates are assumptions.
  • Crop, confidence and foot-snapping are real. Foot keypoints jumped more than 10 cm at the bottom in 56–78% of reps across 5 real single-camera recordings.
  • The zeroed-knee rate depends on noise: 10% mild, 25% realistic, 61% harsh. The bug exists at every level.
  • Timings are Python on a Mac. Expect 3–5× slower on an Orin Nano; the proposed chain stays under a few ms per frame.
